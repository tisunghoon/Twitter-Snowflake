# 린트와 타입 검사

## 현재 상태
Spotless 8.11.0 + google-java-format 1.25.2 AOSP로 서식을 검사합니다.
SpotBugs는 미도입이며 잠재 결함 정적 분석 통과를 주장하지 않습니다.

## 목적
실행 전에 서식, 타입 오류, 정적 분석(코드를 실행하지 않고 결함을 찾는 검사)을 확인한다.

## 사전 조건
[코드 컨벤션](../rules/code-conventions.md)을 기준으로 설정한다.
포매터의 기본값이 공백 4칸 등 현재 규칙과 맞는지 확인하고 불일치를 해결한다.
도구 버전은 고정하고 로컬과 CI에서 같은 설정을 사용한다.

## 실행 방법
- 서식: 구축 후 `./gradlew spotlessCheck`로 검사한다.
- 타입: Java 컴파일로 검사한다. 별도 타입 검사 도구는 추가하지 않는다.
- 잠재 결함: SpotBugs 도입 시 생성되는 태스크와 보고서 경로를 이 문서에 기록한다.
- 통합: 채택한 필수 검사가 `./gradlew check`에 실제로 연결되었는지 확인한다.

컴파일 경고를 모두 오류로 다룰지는 의존성 경고와 기존 코드 영향을 확인해 결정한다.
SpotBugs 미도입 상태에서 정적 분석을 통과했다고 기록하지 않는다.

## 성공 기준
소스 수정 없이 서식 검사를 통과하고 주 코드와 테스트 코드가 컴파일된다.
채택한 분석 도구에서 미해결 필수 위반이 없어야 한다.
분석만으로 동시성 안전성이나 ID 고유성이 증명됐다고 판단하지 않는다.

## 실패 시 확인
파일·줄·규칙 ID와 원인을 확인한다.
오탐을 제외하려면 최소 범위에만 적용하고 이유와 검토 근거를 남긴다.
실패를 없애기 위해 검사 전체를 끄거나 광범위하게 제외하지 않는다.

## 정리 방법
서식 수정 후 diff와 관련 검사를 다시 확인한다.
보고서는 실행별 검증 결과에 연결하며 생성 파일을 소스와 함께 커밋하지 않는다.
