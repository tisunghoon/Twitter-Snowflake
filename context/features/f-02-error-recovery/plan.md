# F-02: 발급 오류와 회복 확인

## 상태와 승인
- 원문 요청: 현재 대화의 F-01~04 문서 작성 및 Agy 작업 지시입니다. GitHub 이슈는 생성하지 않았습니다.
- 상태: 계획 초안 작성. 선행 기능과 상세 계획 확인 후 순차 진행합니다.
- 메인 담당: Herdr 구현 담당 Agy(wG:p3). 실제 전달 시 세션을 확인합니다.
- 선행 기능: F-01의 검증·독립 리뷰·커밋 완료입니다.
- 기준 커밋 / 기존 변경: 구현 시작 시 선행 결과와 작업 트리를 기록합니다.
- 승인 범위: 작업 착수·담당 인계 요청을 받았습니다. D-02~07의 미정 사항은 기존 승인 기록과 대조합니다.

## 사용자 행동
사용자는 발급할 수 없는 상황에서 이유를 구분하는 오류를 받고, 시간이 정상으로 돌아오면 다시 발급받습니다.

## 기존 코드 확인
[AGENT.md](../../AGENT.md), [설계](../../design.md), [결정](../../decisions.md)을 읽습니다.
현재 제품 코드는 없습니다. 구현 시 선행 기능의 코드와 검증 결과를 읽고 재사용할 부분을 적습니다.

## 범위와 계약
D-04·D-06·D-07의 비트·즉시 오류·상태 보존 제안을 기준으로 작성했습니다.
F-01의 최소 오류 보호를 유지하며 실제 생성기와 API를 연결한 실패·회복 시나리오를 확장합니다.
HTTP 오류 계약은 503과 code/message입니다. 메시지 전문보다 오류 코드를 검증합니다.
DB·UI·인증·자동 재시도·시간 조작용 외부 API는 추가하지 않습니다.

## 변경 예상
- core 생성기·예외: 부족한 경계 검사와 실패 후 상태 보존을 보완합니다.
- API 예외 처리기: 도메인 오류만 약속한 응답으로 변환합니다.
- 테스트용 Clock·core/API 테스트: 실제 생성기 상태 전이와 응답을 확인합니다.
- 정확한 파일명은 F-01 결과를 읽은 뒤 기록합니다. 새 의존성이 필요하면 이유와 대안을 제시합니다.

## 완료 조건과 검증
아래 수치·오류 정책은 현재 설계 제안 기준이며 확정 결정이 바뀌면 함께 갱신합니다.

| 조건 | 입력·동작 | 기대 결과 |
|---|---|---|
| AC-01 | 같은 ms의 4096회 성공 후 추가 요청 | SEQUENCE_EXHAUSTED, 기존 상태 보존 |
| AC-02 | 소진 후 다음 ms 요청 | sequence 0으로 회복 |
| AC-03 | epoch+10→9→10→11ms | seq0 → CLOCK_ROLLBACK → seq1 → seq0 |
| AC-04 | epoch 이전·마지막 유효 ms·다음 ms | TIME_OUT_OF_RANGE / 성공 / TIME_OUT_OF_RANGE |
| AC-05 | 세 도메인 오류의 HTTP 요청 | 각각 503과 정확한 code, 임의 예외는 같은 코드로 은폐하지 않음 |

테스트 전용 Clock으로 시간을 제어하고 sleep으로 오류 시점을 맞추지 않습니다.
고정 응답 mock만으로 완료하지 않고 실제 생성기와 API 연결을 검사합니다.
범위 오류 뒤 유효 시각 복귀도 검사해 상태 보존을 확인합니다.
핵심 동작 테스트의 실패를 먼저 확인한 뒤 구현하고 재검증합니다.
선행 검증 결과와 현재 관련 검사 결과를 회귀 기준선으로 기록합니다.
[검증 안내](../../verification/README.md)에 따라 관련 테스트·Java 컴파일·빌드·HTTP 검사를 실행합니다.
현재 명령은 미구축입니다. 선행 기능의 실제 명령을 확인해 plan.md에 기록합니다.
UI가 없으므로 브라우저 검사는 적용하지 않습니다. 미실행 필수 검사는 검증 보류로 보고합니다.

## 결정과 커밋
구현 전에 기존 승인 범위와 계약을 확인하고 미정 사항·변경 필요 사항만 사용자에게 제시합니다.
예정 커밋은 기능 수정과 관련 검증·실행 안내를 논리 단위로 나눕니다. 무관한 리팩터링은 제외합니다.
새 컨텍스트 리뷰어에게 계획·기준 커밋·새 파일 포함 diff·코드·실행 증거를 제공합니다.
실행 증거는 [verification.md](verification.md), 독립 리뷰는 [review.md](review.md)에 남깁니다.
차단 결함 수정·재검증·필요한 재리뷰 후 해당 변경만 커밋하고 push는 하지 않습니다.
