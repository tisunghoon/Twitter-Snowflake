# F-NN: 사용자 행동과 결과

## 상태와 승인
- 이슈 URL·번호 또는 원문 요청 위치: 미지정
- 이슈 내용 확인 날짜: 계획 시 기록
- 상태: 계획 중
- 메인 담당: 미지정
- 선행 기능: 미정
- 기준 커밋 / 기존 미커밋 변경: 계획 시 기록
- 사용자 승인: 미승인
- 승인 범위와 변경 이력: 없음

## 사용자 행동
입력·행동·관찰할 결과를 적는다.

## 기존 코드 확인
읽은 지침·관련 코드·재사용할 기능·기존 동작과 제약을 적는다.

## 범위와 계약
포함·제외 범위, 관련 설계 결정과 확정 여부를 적는다.
API·DB·설정·인증·접근 제어 변경과 호환성 영향을 적는다. 해당 없으면 이유를 적는다.
새 의존성의 필요성과 기존 도구를 쓰는 대안을 적는다.

## 변경 예상
파일별 역할과 변경 이유를 적는다. 존재하지 않는 경로는 예정으로 표시한다.

## 완료 조건
이슈의 AC 번호를 유지하고 정상·실패·경계 입력별 기대 결과를 적는다.
정확성에 필요한 동시성 보호와 오류 검사를 후속 기능으로 미루지 않는다.

## 검증 계획
테스트·타입 검사·빌드·실행 명령과 기대 결과를 적는다.
UI가 있으면 브라우저 정상·실패 검사, 없으면 적용하지 않음을 적는다.
미구축 명령, 필요한 환경, 차단 사유를 명시한다.
기능·버그 수정은 먼저 실패를 확인할 핵심 동작 테스트를 지정한다.
F-02부터 직전 검증 결과와 현재 관련 검사 결과를 회귀 기준선으로 기록한다.
F-01은 기존 구현이 없으므로 기존 회귀 기준선 없음으로 기록한다.

|---|---|---|
| AC-01 | 계획 시 작성 | 계획 시 작성 |

## 결정이 필요한 사항
기존 코드와 지침에서 답을 찾을 수 없는 질문만 적는다.
승인 이후 이슈가 변경되면 차이·영향·재승인 범위를 기록한다.

## 커밋과 리뷰
예정 커밋 단위를 적고 기능 외 변경을 제외한다.
새 컨텍스트 리뷰어에게 계획·설계·기준 커밋·전체 diff·코드·테스트·실행 증거를 전달한다.
실행 결과는 verification.md, 발견 사항·수정·재검토 결과는 review.md에 기록한다.
