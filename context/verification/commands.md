# 실행·빌드·검증 명령

## 현재 상태
준비 예정. 아래 명령은 구현할 인터페이스이며 현재 실행 가능하지 않다.
Wrapper와 각 태스크·스크립트를 만든 뒤 실제 실행으로 검증하고 이 상태를 갱신한다.

## 목적과 사전 조건
저장소 루트에서 [환경 점검](environment.md)을 마친 뒤 실행한다.
빌드·검증 명령은 사용자 입력을 기다리지 않고 종료해야 한다.

## 실행 방법
| 예정 명령 | 역할 | 성공 기준 |
|---|---|---|
| `./scripts/doctor.sh` | 환경 점검 | 필수 조건 충족, 종료 코드 0 |
| `./gradlew spotlessCheck` | 서식 검사 | 서식 위반 없음 |
| `./gradlew check` | 컴파일·테스트·연결된 분석 | 모든 필수 검사 통과 |
| `./gradlew bootJar` | 실행 JAR 생성 | 실행할 JAR 경로 식별 |
| `./scripts/smoke-test.sh` | 실제 서버 HTTP 검사 | 응답 검증과 서버 정리 성공 |
| `./scripts/verify.sh` | 위 절차 통합 | 필수 단계 모두 통과 |

개발용 서버 명령은 `./gradlew bootRun`을 사용할 예정이다.
워커 ID와 포트 전달 옵션은 실제 설정 바인딩을 구현한 뒤 복사 가능한 명령으로 추가한다.
서식 자동 수정은 별도 `spotlessApply`로 실행하고 diff를 확인한다. 검사 명령이 소스를 수정하지 않는다.

## 결과 기록
통합 스크립트는 단계별 시작·종료 시각, 명령, 종료 코드, 로그 경로를 기록한다.
실행별 디렉터리를 사용해 이전 실패 로그를 덮어쓰지 않는다.
테스트 0건이나 필수 태스크 미연결을 통과로 오인하지 않도록 실행 건수와 연결 상태를 확인한다.
최초 실패 단계에서 의존 작업을 중단하고 후속 단계는 미실행으로 표시한다.

## 실패 시 확인
실패한 단계의 원본 로그부터 확인한다. 재실행 성공만으로 최초 실패를 지우지 않는다.
명령 자체가 없으면 환경 미구축으로 기록하며 테스트 실패와 구분한다.
로그를 파일로 보내더라도 원래 명령의 실패 종료 코드를 유지한다.

## 정리 방법
통합 스크립트는 종료·오류·중단 시 자신이 만든 서버와 임시 자원만 정리한다.
보고서는 남기고, 보관 기간과 삭제 방법은 구축 시 정한다.
