# 기능 계획과 리뷰 인계 형식

기능 하나는 사용자 행동 하나의 성공·실패 경로를 끝까지 구현한다.
[기능 템플릿](../../../features/template.md)을 복사해 plan.md를 작성한다.
환경/core/API 같은 계층만으로 별도 사용자 기능을 만들지 않는다.

## 필수 계획 항목
- 기능 ID, 담당 메인 에이전트, 상태, 선행 기능.
- 사용자 행동과 관찰 가능한 결과.
- 포함·제외 범위, 성공·실패·경계의 완료 조건.
- 설계 결정 ID와 승인 상태.
- 변경 예상 파일, API·DB·설정 영향과 호환성.
- 실행할 검사, 실제 동작 확인 방법, 환경과 미정 항목.
- 기준 커밋, 기존 변경, 예정 커밋 단위.
- 사용자 승인 범위와 변경 이력.

## 독립 리뷰 인계
새 컨텍스트 리뷰어에게 승인 계획, 관련 설계·규칙, 기준 커밋과 현재 diff,
코드·테스트 위치, 실행 명령·결과·미실행 항목을 제공한다.
새 파일과 미커밋 변경도 검토 대상에 포함한다.
전체 구현 대화와 구현자의 결론만으로 판단하게 하지 않는다.
리뷰어는 심각도·파일/줄·문제·근거·기대 동작·차단 여부를 기록한다.
메인 에이전트가 수정하고 재검증하며 필요 시 재리뷰한다.
필수 증거가 없으면 검증 보류이며, 다음 기능으로 완료 처리해 넘기지 않는다.
