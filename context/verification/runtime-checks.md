# 실제 서버와 브라우저 확인

## 현재 상태
F-01~04 서버·단일/다중 워커 스크립트를 구축하고 실제 HTTP·실패/중단 검사를 실행했습니다.
UI가 없으므로 브라우저 자동화는 현재 적용하지 않는다.

## 목적과 사전 조건
스모크 테스트(주요 기능이 실행되는지 빠르게 확인하는 검사)로 실제 JAR을 검증한다.
단위 테스트와 같은 결과를 보장하는 전체 검사를 대신하지 않는다.
빌드한 JAR 경로, 검증용 포트, 워커 ID, HTTP·JSON 검사 도구가 필요하다.

## 실행 방법
구축할 `./scripts/smoke-test.sh`는 다음 순서로 동작한다.

1. 실행 JAR 하나를 정확히 식별하고 설정값을 기록한다.
2. 검증용 포트에서 서버를 시작하고 자신이 만든 프로세스 식별자를 보관한다.
3. 준비 확인을 제한 시간 안에서 반복한다. 포트 연결만으로 준비 완료로 판단하지 않는다.
4. `POST /api/ids`를 호출해 HTTP 200과 JSON 구조를 검사한다.
5. id 문자열, 워커 ID, 순번 범위, ID에서 복원한 시각과 응답 시각의 일치를 확인한다.
6. 제한된 수의 순차 호출에서 중복과 증가 여부를 확인하고 서버를 종료한다.

준비 확인용 경로나 요청 방식, 제한 시간·호출 수는 구현 시 확정한다.
발급 요청으로 준비를 확인했다면 순번이 이미 소비됐다는 점을 후속 검사에 반영한다.
시계 역행과 순번 소진은 제어된 Clock 테스트에서 검사한다.

## 성공 기준
준비·요청·응답 검사와 프로세스 정리가 모두 성공해야 한다.
서버가 먼저 종료되거나 요청이 시간 제한을 넘으면 실패다.

## 실패 시 확인
서버 시작 로그, 요청 상태 코드, 비밀 값을 제외한 응답, 종료 코드를 보관한다.
포트 충돌·설정 오류·HTTP 계약 위반을 구분한다.
UI를 도입하면 브라우저 검사 대상 URL, 화면 단언, 콘솔·네트워크 오류, 캡처 위치를 추가한다.

## 정리 방법
성공·실패·중단 모두에서 자신이 시작한 서버만 종료하고 종료 여부를 확인한다.
이름으로 Java 프로세스 전체를 종료하지 않는다. 정리 실패도 결과에 표시한다.
