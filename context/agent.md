# Snowflake 기능 개발·학습 파트너

## 역할
사용자는 목표·범위·주요 설계를 결정한다.
메인 에이전트는 기능 하나의 계획 → 구현 → 자체 검증 → 수정·재검증·커밋을 끝까지 담당한다.
독립 리뷰 에이전트는 새 컨텍스트에서 요구사항과 실제 diff·코드·테스트를 읽고 판정한다.
학습 질문 담당이 있으면 설명을 지원하되 설계를 자동 확정하거나 코드를 별도로 수정하지 않는다.
2026-11-12 사용자 요청에 따라 이전의 Agy 구현·Codex 최종 검증 고정 분담을 대체한다.

## 시작
[실습 스킬](skills/snowflake-practice/SKILL.md)을 적용한다.
[기능 목록](tasks.md), [진행 상태](progress.md), [결정](decisions.md)을 확인한다.
구현 전 [규칙](rules/workflow.md)과 [검증 안내](verification/README.md)를 읽는다.
세부 verification 문서는 현재 변경과 관련된 항목만 추가로 읽는다.
세션 종료·단계 전환 때 progress의 최신 재개 블록을 갱신하고 이력은 Git으로 보존한다.
이 파일과 스킬은 프로젝트 문서이며 전역 등록이나 루트 AGENTS.md 자동 로딩을 전제하지 않는다.

## 현재 범위
Java + Spring Boot는 확정됐다. 버전·비트·epoch·오류·워커 정책은 결정 기록의 상태를 따른다.
제품 코드와 빌드 환경은 아직 없다. 기능별 흐름 채택은 F-01 구현 승인과 별개다.
원문: https://blog.x.com/en/engineering/announcing-snowflake
참고 노트: https://app.notion.com/p/40b04552316d81c3b579efa7fab1f5b6
시간·워커·순번 조합, 정렬 특성, 동시성, 시계 역행을 학습한다.

## 협업
설명은 기술 용어를 유지하고 쉬운 예시와 연결한다. 비유의 한계를 밝힌다.
원문 사실·추가 자료·제안·확정을 구분한다. 기존 답을 먼저 확인한다.
한 기능 계획은 한 번 승인받고 범위 안의 수정·재검증은 계속 진행한다.
사용자와 다른 에이전트의 변경을 보존한다. 구현을 계층별 에이전트에 분산하지 않는다.
문서 작성과 외부 메시지 전송은 구분한다. 요청 없는 외부 전송은 하지 않는다.

## 독립 리뷰와 완료
리뷰어에게 승인 계획·설계·규칙·기준 커밋·diff·실행 증거를 제공한다.
전체 구현 대화는 넘기지 않는다. 구현자의 통과 주장을 검토 근거로 대신하지 않는다.
리뷰어는 읽기 전용이며 수정은 메인 에이전트가 한다.
Codex 협업 도구에서는 fork_turns="none"인 별도 리뷰 에이전트를 만들고 templates/review.md의 자료만 제공한다.
다른 호스트에서는 대화 이력을 상속하지 않는 새 세션을 사용한다. 기존 동료 패널을 자동으로 독립 리뷰로 간주하지 않는다.
필수 검사 미실행, 독립 리뷰 부재, 차단 결함이 있으면 완료로 표시하지 않는다.
실행 증거와 실제 동작, 검토한 코드와 최종 커밋의 일치가 완료 근거다.

## 기록 위치
공통 설계는 design·architecture, 확정 상태는 decisions에 기록한다.
기능 계획·실행 증거·독립 리뷰는 features의 해당 기능 폴더에 기록한다.
tasks는 기능 목록, progress는 재개 위치를 담는다. 중복된 상태 기록이 어긋나지 않게 갱신한다.
