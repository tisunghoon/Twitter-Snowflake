## 완료 조건과 구체적 검증

| AC | 입력·실행 | 단언 |
|---|---|---|
| AC-01 | 같은 JAR, 서로 다른 포트, worker 1/2 | 각 자식 생존·30초 내 실제 POST 200·JSON 확인; 응답에서 올바른 워커 복원 |
| AC-02 | 고정된 epoch+10ms, worker 1/2 각각 2048회 | 합계 4096개 고유, 각 워커 순번 0~2047, 복원 시각 같음 |
| AC-03 | 실제 두 프로세스에 워커당 2048회 | 4096개 모두 200·고유, 서버별 워커·비트 복원·timestamp 일치; 준비 발급과 본 검사 집계를 구분 |
| AC-04 | 실제 JAR을 워커 미설정/-1/1024로 별도 기동 | 제한 시간 내 비정상 종료와 설정 원인 로그; 생존하거나 서버 응답하면 실패; 양 경계 0/1023의 정상 설정은 컨텍스트 회귀 검사 |
| AC-05 | 아래 실패 주입과 SIGINT/SIGTERM | 비정상 종료 코드·로그 보존·자기 자식 종료·기존 외부 리스너 생존 |
| AC-06 | README 실행 명령과 한계 | Java 21·같은 JAR·서로 다른 포트/워커 명시; 같은 워커 재사용·재시작 중복 가능성과 전역 엄격 정렬 미보장 명시 |

실제 두 서버 시계가 같다고 가정하지 않습니다. 동일 ms 증명은 AC-02의 제어 Clock에서 수행합니다.
포트는 서로 다른 사용 가능 포트를 입력받으며 선점 검사 뒤에도 발생 가능한 bind 실패는 로그·자식 종료로 판별합니다. 기존 프로세스를 kill하지 않습니다.
각 서버의 준비 POST 성공은 1회로 제한하고 본 검사 2048회와 별도 집계합니다. 준비 발급을 포함해 워커당 4096 미만을 보장합니다. HTTP 요청은 순차 또는 제한된 작업자로 수행하며 자동 재시도로 503을 숨기지 않습니다.
응답의 id는 십진 문자열을 Python int로 바꾸고 41/10/12 비트와 epoch로 독립 복원합니다. 생성기 Decoder의 결과만 믿어 순환 단언하지 않습니다.

## 실행 단계와 실패 재현
1. F-03 기준 커밋·전체 검사 결과와 현재 회귀 결과를 기록합니다. JAR 하나와 JVM 21을 정확히 지정합니다.
2. 같은 시각 두 생성기 단위 검사를 먼저 추가합니다. 기존 코드가 이미 통과하면 GREEN을 기록하고 제품을 고의로 깨뜨리지 않습니다.
3. 첫 자식을 시작하기 전에 빈 PID 목록을 초기화하고 EXIT/INT/TERM 정리 핸들러를 설치합니다. 자식 생성 직후 PID를 등록하며, 자식이 없거나 하나만 있는 상태에서도 정리는 안전해야 합니다. 준비·요청·전체 작업에 timeout(각각 30초·5초·120초)을 두고 정상·실패에서 동일한 정리 경로를 사용합니다. 자식 종료는 TERM→최대 5초 대기→필요 시 자기 PID만 KILL→wait로 회수하고 정리 실패도 보고합니다.
4. 두 번째 서버 worker=-1로 기동해 첫 서버까지 정리되는지 검사합니다. 정상 서버에 잘못된 검사 URL을 지정해 응답 실패 후 두 자식이 종료되는지 검사합니다. 테스트 옵션은 스크립트에만 추가합니다.
5. 테스트 리스너가 두 번째 포트를 선점한 상태에서 실행해 충돌을 재현합니다. 스크립트 실패 후 첫 자식 종료와 기존 리스너의 응답 유지·PID 생존을 확인하고 테스트가 만든 리스너만 별도로 정리합니다.
6. 테스트 전용 시작 장벽으로 첫 자식 PID 등록 후 두 번째 시작 전에 멈춘 상태를 재현하여 SIGINT/SIGTERM과 두 번째 시작 실패를 각각 주입합니다. 첫 자식이 종료·회수되고 기존 리스너가 생존하는지 확인합니다. 자식 둘이 시작된 뒤에도 스크립트에 SIGINT/SIGTERM을 각각 보내고 두 PID 종료·wait 회수와 원래 리스너 생존을 확인합니다. 하네스 자체도 finally/trap으로 잔여 자식을 정리합니다.
7. 워커 미설정/-1/1024 실제 시작 검사를 수행합니다. 현재 셸의 SNOWFLAKE_WORKER_ID나 설정 파일이 미설정을 가리지 않도록 테스트 실행 환경에서 해당 설정만 제거합니다. 전체 환경 변수는 출력하지 않습니다.
8. 전체 검증에 다중 워커 검사를 연결하고 README 명령을 실제 실행합니다. 필수 검사 실패는 통과로 처리하지 않습니다.

## 실제 실행 대조
선행 F-03 완료 커밋1e3fca0에서 재개했습니다. 기존 config 테스트를 재사용하고 SnowflakeMultiWorkerTest를 추가했습니다. 실제 구현은 shell 진입점→Python 오케스트레이터입니다. EXIT는 try/finally, INT/TERM은 첫 자식 전 signal handler로 대응하며 신호 핸들러는 중단 플래그만 설정합니다. Popen 반환 직후 PID를 등록하므로 비동기 예외로 등록이 누락되는 구간을 피합니다. 각 반복/시작/대기에서 중단을 확인하고 정리합니다. 테스트 전용 장벽·오류 주입 옵션은 스크립트에만 있습니다. 고정시각 검사는 기존 생성기로 GREEN, 새 스크립트는 최소골격에서4096건 결과 부재 단언으로 RED를 확인한 뒤 구현했습니다. test_worker_config.py는 실제 JAR의 누락/-1/1024 시작 실패를 환경 기본값을 제거하고 검사합니다.
