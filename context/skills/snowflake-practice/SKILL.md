# Snowflake 실습 지원

[역할 문서](../../agent.md)를 읽고 사용자가 요청한 단계부터 진행한다.
개념 설명만 요청하면 전체 설계나 구현을 시작하지 않는다.

## 1. 자료와 학습 출발점

원문과 기존 노트·설계·저장소를 확인한다. 원문 접근 실패 시 읽은 범위를 밝히고,
접근 가능한 원문 또는 필요한 발췌를 요청한다. 제목만으로 내용을 재구성하지 않는다.
학습 목표, 익숙한 언어, 가능한 시간은 기존 답을 우선 사용한다.
미정이면 개념 설명은 계속하고 환경에 의존하는 구현 결정 직전에 묻는다.

## 2. 이해할 수 있는 개념 노트

concepts.md에 각 개념의 필요성, 쉬운 비유, 작은 구체적 예시, 실제 용어,
이번 실습에서 확인할 행동, 출처를 연결한다. 다음 개념을 학습 진도에 맞춰 다룬다.

- 고유 ID가 필요한 이유와 여러 서버의 중복 문제.
- timestamp, worker ID, sequence의 역할과 조합.
- 비트·시프트·마스크, epoch, 숫자로 표현할 수 있는 범위.
- 같은 시간의 여러 요청, 동시성, 시계 역행과 시퀀스 한도.
- 고유성·단일 생성기의 단조 증가·여러 서버의 대략적 시간 정렬 차이.

작은 가상 비트 배분으로 생성과 복원을 손으로 따라가게 한다.
예시 값은 실제 채택 값과 구분한다. 원문에 없는 구체적 비트 배분이나
시계 역행 정책은 추가 설계임을 표시하고 근거가 필요하면 1차 자료를 조사한다.

## 3. 구현 계약 설계

design.md에 목표·제외 범위, 실행 환경, API와 오류 계약, 상태 전이,
동시성 제어, 시간 주입 방식, 테스트 기준을 기록한다.
각 선택은 제안/확정/위임 결정 상태와 이유를 가진다.

| 결정 | 함께 확인할 조건 |
|---|---|
| 비트 배분 | 부호 비트 포함 여부, 시간 수명, 워커 수, ms당 생성량, 범위 초과 |
| epoch | UTC 기준의 명시적 시각, 시작 전 시간, 표현 가능한 마지막 시간 |
| 워커 ID | 설정/할당 주체, 중복 방지 책임, 여러 프로세스·재시작 시 재사용 |
| 시퀀스 | 새 ms에서 초기화, 최대값, 소진 시 대기/오류, 대기 종료 조건 |
| 시계 역행 | 탐지 조건, 오류/대기/논리 시간 중 선택, 재개 조건·제약 |
| 동시성 | 상태 갱신의 원자성, 단일/다중 인스턴스 경계 |
| 정렬 | 보장 대상과 보장하지 못하는 다중 서버의 실제 시간 순서 |

수명·용량은 채택 비트 수에서 계산한다. 재시작, 워커 중복, 시간 범위 밖에서
고유성이 무조건 보장된다고 쓰지 않는다. 영속화·분산 워커 할당 등을 제외하면
실습의 전제와 보장 범위에 명시한다. 작은 토이에 인프라를 자동 추가하지 않는다.
주요 미정 사항은 선택지와 추천 이유를 사용자에게 요청하고 decisions.md에 반영한다.

## 4. Agy 구현 task 작성

설계를 [인계 형식](references/task-format.md)에 맞춰 tasks.md로 분해한다.
학습 목표 → 설계 결정 → task → 검증 기준의 연결을 유지한다.
공통 계약에 의존하는 task는 그 계약이 확정되기 전 실행 가능으로 표시하지 않는다.
순서는 환경·시간 추상화 → 생성/복원 → 경계·동시성 정책 → 검증·실행 안내를
기본으로 하되 실제 설계에 맞게 조정한다. 불필요한 REST API·DB·UI는 추가하지 않는다.
문서만으로 Agy가 구현할 수 있도록 입력·출력·오류·경계 기대 결과를 구체화한다.

## 5. 실습 지원과 결과 검토

3패널 Agy는 구현·테스트 담당이고, 4패널 Agy는 학습 Q&A 담당이다.
3패널 Agy의 구현·테스트 통과 보고 후 Codex가 최종 코드 리뷰와 검증을 수행한다.
인계받을 자료는 변경 코드 버전/diff, 실행 환경, 테스트 명령·결과, 알려진 제한이다.
구현뿐 아니라 테스트 코드의 단언과 누락도 읽고 관련 테스트를 직접 실행한다.
리뷰는 context/review.md에 코드 버전, 설계 대비 결과, 심각도와 파일/위치가 있는
발견 사항, 실행 증거, 미실행 항목, 통과/수정 필요/검증 보류 판정으로 남긴다.
수정은 3패널 Agy에게 연결하고 변경된 결과를 재검증한다.
4패널 Agy의 설명·제안은 기존 확정 설계를 자동 변경하지 않는다.

사용자의 막힌 지점에는 관찰한 현상 → 관련 개념 → 작은 재현 → 확인 방법으로 답한다.
Agy의 구현과 테스트를 확정 설계에 대조한다. 아래 사례의 기대 결과를 정책에서 도출한다.

- 단일 워커의 같은 ms 연속 호출, ms 전환, 시퀀스 한도 직전/도달/초과.
- 여러 스레드의 중복 여부와 생성 수, 서로 다른 워커의 동일 시각 생성.
- 시계 역행과 회복, 시간이 계속 멈춘 경우, epoch/워커/시간 범위 경계.
- 비트 필드 복원, 약속한 범위의 정렬, 재시작의 보장 범위.

실제 sleep에만 의존하지 않고 제어 가능한 시계를 사용하도록 task에 명시한다.
시퀀스 소진·역행 테스트가 무한 대기하지 않도록 시간 진행 또는 종료 조건을 설계한다.
동시 호출의 완료 순서를 생성 순서로 간주하는 정렬 테스트를 만들지 않는다.
검증 기록에는 실행 명령·환경·결과·미실행 항목을 남긴다.
오류가 나오면 설계 변경이 필요한지 구현 수정인지 구분하고 관련 결정과 task를 갱신한다.
