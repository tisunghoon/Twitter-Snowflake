# 검증 환경 안내

## 현재 상태
준비 예정. 2026-11-12 확인 기준 제품 코드, Gradle Wrapper, 검증 스크립트, CI 설정은 없다.
이 폴더는 구축할 환경의 명세다. 문서 생성은 구현·배포 승인이나 설계 정책 확정을 뜻하지 않는다.
기술과 정책의 확정 여부는 [결정 기록](../decisions.md)을 따른다.

## 목적과 읽는 순서
AI가 실행 조건, 명령, 성공 기준, 실패 근거를 같은 순서로 확인하도록 한다.

| 순서 | 문서 | 확인할 내용 |
|---|---|---|
| 1 | [환경](environment.md) | JVM, 도구, 설정 |
| 2 | [명령](commands.md) | 실행 위치와 검증 순서 |
| 3 | [정적 분석](static-analysis.md) | 서식, 타입, 결함 검사 |
| 4 | [테스트](testing.md) | 필수 사례와 단언 |
| 5 | [테스트 데이터](test-data.md) | 시계와 워커 설정 |
| 6 | [실행 확인](runtime-checks.md) | 서버, HTTP, 로그, 종료 |
| 7 | [CI](ci.md) | PR 검사와 보고서 |
| 8 | [스테이징](staging.md) | 도입 조건과 배포 후 검증 |

## 최소 검증 절차
환경 확인 → 정적 분석·테스트 → 실행 파일 빌드 → 실제 서버 HTTP 검사 → 결과 기록 순서로 진행한다.
문서만 수정하면 링크, 설계와의 일치, 준비 상태 표기를 검사한다.
필수 단계가 실행되지 않았으면 전체 통과로 표시하지 않는다.

## 결과와 파일 위치
실행 스크립트는 루트의 `scripts/`, CI 설정은 `.github/workflows/`에 만들 예정이다.
자동 보고서는 `build/verification/<실행 식별자>/`에 모으고 Git에서 제외한다.
결과에는 코드 버전과 미커밋 변경 여부, 실행 환경, 명령, 종료 코드, 로그 위치를 포함한다.
진행 상태는 [progress.md](../progress.md), 최종 리뷰는 생성 예정인 `context/review.md`에 기록한다.
실패 로그에 자격 증명이나 환경 변수 전체를 출력하지 않는다.
