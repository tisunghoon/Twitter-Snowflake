# 프로젝트 훅 명세

현재는 문서만 작성됐다. 실행 스크립트와 에이전트 호스트 연결은 아직 없다.
이 폴더를 만들었다고 위험 작업이나 완료 선언이 자동으로 차단되는 것은 아니다.

| ID | 명세 | 실행 시점 |
|---|---|---|
| H-01 | [위험 작업 차단](dangerous-actions.md) | 위험 도구 호출 전 |
| H-02 | [민감 변경 감지](sensitive-changes.md) | 보호 파일 수정 전·작업 종료·커밋 전 |
| H-03 | [기능 단위 검증](feature-verification.md) | 수정 묶음 종료·독립 리뷰 전 |
| H-04 | [완료 게이트](completion-gate.md) | 기능 완료 선언 전 |

## 공통 본문 형식
모든 훅은 다음 제목과 순서를 사용한다.

1. 식별과 상태
2. 실행 시점
3. 적용 범위
4. 입력과 증거
5. 검사 명령
6. 판정 기준
7. 실패 동작
8. 시간 제한
9. 예외 처리
10. 출력 정책
11. 검사기 오류 처리
12. 재검사 조건

## 연결과 구축 순서
위험 작업·민감 변경 검사 → 실제 verify.sh 구축 → 기능 검증 → 완료 게이트 순서다.
공통 검증 방법은 [verification](../verification/README.md), 작업 절차는 [workflow](../rules/workflow.md)를 따른다.
예정 스크립트는 저장소 루트의 scripts/hooks와 scripts/verify.sh에 둔다.
현재 호스트의 이벤트·입력·종료 코드·차단 지원을 확인하고 어댑터를 만든 뒤 연결한다.
호스트 미지원과 검사 통과를 구분한다. 차단 전에 판정을 마쳐야 하는 검사는 비동기 알림으로 대체하지 않는다.
훅 검사를 우회하는 도구가 있으면 범위를 밝히고 샌드박스·권한 제한으로 보완한다.

## 구축 완료 기준
허용·차단·예외·시간 초과·검사기 누락·로그 마스킹을 각각 시험한다.
관련 검사는 경로 밖 접근·심볼릭 링크·새 파일·스테이징 차이·오래된 검증 증거도 확인한다.
완료 게이트는 일반 답변과 중단을 막지 않는지, 반복 한도가 유지되는지 시험한다.
설치한 훅의 버전·지원 호스트·검증 결과를 기록한 뒤 상태를 활성으로 바꾼다.

## 보류 항목
변경 파일 포맷 훅은 Java 포매터 확정 후 별도 명세로 추가한다.
매 수정 전체 테스트, 자동 LLM 리뷰 호출, 자동 스테이징·커밋·push·배포는 넣지 않는다.
