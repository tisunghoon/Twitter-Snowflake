# 이슈 제목: 사용자 행동과 결과

이 템플릿은 이슈 본문에 사용한다. 대괄호 안내는 실제 요청으로 바꾼다.
코드 조사로 알 수 있는 파일명·실행 명령은 에이전트가 계획 단계에서 확인한다.

## 목표
[누가 어떤 행동을 하고 어떤 결과를 얻는가]

## 먼저 할 일
- 저장소 지침과 관련 코드를 읽는다.
- 기존 구현과 재사용 가능한 기능을 확인한다.
- 변경 파일, API·DB·설정 영향, 검증 방법을 제시한다.
- 계획 승인을 받은 뒤 구현한다.

## 완료 조건
- [ ] AC-01: [정상 입력과 기대 결과]
- [ ] AC-02: [잘못된 입력과 거부 결과]
- [ ] AC-03: [실패 시 사용자가 볼 상태와 보존할 입력]
- [ ] AC-04: [접근 권한 또는 기능의 주요 경계 조건]

조건은 관찰하거나 테스트할 수 있게 적는다.
정책이 미정이면 추측하지 않고 계획 단계의 질문으로 남긴다.

## 범위
- 포함: [이번 기능에서 구현할 동작]
- 제외: [이번에 구현하지 않을 동작]
- 무관한 리팩터링은 하지 않는다.
- 새 의존성은 필요성과 기존 도구를 쓰는 대안을 설명한다.

## 검증
- 완료 조건별 검증 방법과 기대 결과를 제시한다.
- 관련 테스트, 타입 검사, 빌드를 실제 실행한다.
- UI 변경은 브라우저에서 정상·실패 상태를 확인한다.
- 실행하지 못한 검증은 이유와 영향을 기록한다.
- 새 컨텍스트의 독립 리뷰를 받고 발견된 결함을 수정·재검증한다.
