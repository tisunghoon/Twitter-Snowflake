# CI 검증

## 현재 상태
준비 예정. GitHub Actions 설정과 필수 검사 규칙은 아직 없다.
저장소의 원격 설정과 권한을 확인한 뒤 구축한다.

## 목적과 사전 조건
CI(변경할 때마다 자동으로 빌드와 테스트를 실행하는 과정)에서 로컬과 같은 검사를 수행한다.
먼저 로컬 검증 명령이 재현 가능해야 한다. 실행 JVM과 Wrapper 버전을 고정한다.

## 실행 방법
생성 예정 파일은 `.github/workflows/verify.yml`이다.
PR과 기본 브랜치 변경에 실행하는 구성을 제안한다.

1. 검토 대상 코드를 가져오고 실행한 커밋을 기록한다.
2. 지정 JDK를 준비하고 Gradle Wrapper를 검증한다.
3. 서식·컴파일·테스트·채택한 정적 분석을 실행한다.
4. 실행 JAR을 빌드하고 실제 서버 HTTP 검사를 실행한다.
5. 성공·실패에 관계없이 가능한 보고서와 로그를 업로드한다.

액션 버전, 실행 제한 시간, 캐시 키, 산출물 보관 기간은 구축 때 고정한다.
캐시는 속도를 위한 것이며 오래된 검사 결과를 새 실행의 증거로 사용하지 않는다.
필수 검사 이름을 정한 뒤 저장소 보호 규칙과 연결한다.

## 성공 기준
필수 작업이 모두 실행돼 성공하고 보고서에서 테스트 건수를 확인할 수 있어야 한다.
생략된 작업이나 실행 자체가 없던 PR을 통과로 간주하지 않는다.
문서 변경만 검사할 때의 예외는 명시적으로 정의하고 필수 검사와 충돌하지 않게 한다.

## 실패 시 확인
실패한 작업, 커밋, JDK, 명령, 로그를 확인하고 같은 버전을 로컬에서 재현한다.
외부 PR 검증에는 배포 자격 증명을 제공하지 않는다.
일반 검증 권한은 필요한 읽기 권한으로 제한한다.

## 정리 방법
작업 종료 시 서버·임시 자원을 정리하고 보고서는 보관 기간 후 삭제한다.
CI 성공이 스테이징 배포 승인이나 재시작 이후 고유성 보장을 뜻하지 않는다.
