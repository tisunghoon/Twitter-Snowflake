# Agy 인계 형식

tasks.md 첫머리에 읽을 문서, 확정된 실행 환경, 공통 API/오류 계약,
결정 버전 또는 Git 커밋, 전체 의존 순서, 실행 가능한 task와 차단된 task를 적는다.
아래 형식을 각 task에 적용하되 미정 값은 추측으로 채우지 않는다.

## T-번호: 행동과 결과를 드러내는 제목

- 상태: 준비 / 차단 / 진행 / 검증 대기 / 완료
- 담당: Agy(구현), Codex(설계·검토), 사용자(학습·결정) 중 실제 책임자
- 목적: 어떤 학습 목표와 기능을 달성하는가
- 근거: design.md 절과 D-번호 결정 링크
- 선행 task: ID 또는 없음
- 작업 범위: 파일·모듈과 책임 경계; 미정 경로는 제안이라고 표시
- 구현 계약: 입력, 출력, 상태 변경, 오류, 경계 동작
- 제외 범위: 이 task에서 다루지 않을 항목
- 완료 조건: 외부에서 관찰하거나 검증할 수 있는 결과
- 검증: 준비 조건 → 실행 → 예상 결과, 실행 명령이 확정됐다면 명령 포함
- 학습 확인: 사용자가 직접 실행/변경/설명해 볼 작은 활동
- 차단 사유: 필요한 사용자 답 또는 선행 결정; 없으면 없음
- 결과 기록: 변경 파일, 실제 실행 명령과 결과, 남은 제한

“테스트 통과”만으로 완료 조건을 대신하지 않는다.
예를 들어 동시성 task는 확정된 워커·시간·스레드·요청 조건에서
성공한 생성 수와 고유 ID 수가 같아야 한다는 식으로 검증 가능하게 작성한다.
시계 역행 task는 채택 정책에 따른 오류 종류 또는 대기·회복 동작을 명시한다.
언어나 빌드 도구가 미정이면 실행 명령을 만들어내지 않는다.

설계 변경은 먼저 결정 기록에 남기고 영향받는 task를 수정한다.
Agy가 완료했다고 보고한 내용과 Codex가 실제 확인한 결과를 분리한다.
