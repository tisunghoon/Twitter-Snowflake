# 위험 작업 차단

## 식별과 상태
- 훅 ID: H-01
- 정책 버전: 0.1
- 상태: 명세 작성 / 스크립트 미구축 / 호스트 미연결
- 아래 시간·명령은 구축 기준이며 실제 작동을 검증한 값이 아니다.

## 실행 시점
위험 가능성이 있는 도구 호출을 실제 실행하기 전에 검사한다.
명령 제출 뒤 관찰하는 이벤트만으로는 사전 차단을 구현했다고 표시하지 않는다.

## 적용 범위
셸 실행, Git 변경 폐기·강제 푸시, 파일 삭제, 파일 외부 전송을 대상으로 한다.
도구별로 감지·차단 가능한 범위를 확인한다. 셸 밖의 편집·MCP·업로드 경로도 구분한다.
운영 자격 증명과 배포 권한을 개발 에이전트에 제공하지 않는 제한을 먼저 적용한다.

## 입력과 증거
도구 종류, 작업 내용, 작업 디렉터리, 정규화된 실제 대상 경로, 대상 환경, 승인 근거를 받는다.
심볼릭 링크의 실제 대상도 확인한다. 명령 문자열의 특정 단어만으로 판정하지 않는다.
승인 근거는 사용자의 대상·행위·유효기간이 확인되는 기록이어야 한다.

## 검사 명령
예정: `./scripts/hooks/check-action`.
구조화된 입력 전달 방식과 호스트별 차단 응답은 구현 시 확정한다.
검사는 대상 명령을 실행하지 않는다.

## 판정 기준
승인 없는 강제 푸시·변경 폐기, 저장소 밖의 대량 삭제, 비밀 파일 출력·외부 전송은 실패다.
운영 DB 초기화·삭제·마이그레이션 요청도 검사하되 현재 프로젝트에는 DB가 없다.
대량 삭제의 수량·허용 경로는 구축 시 명시한다. 미정 상태에서 임의로 허용하지 않는다.
검사 대상의 실제 경로나 환경을 판단할 수 없으면 판정 불가다.

## 실패 동작
실패·판정 불가는 해당 위험 작업을 차단하고 대상 확인 또는 구체적인 승인을 요청한다.
안전한 대안이 있으면 설명하되 차단된 작업을 다른 도구로 우회하지 않는다.

## 시간 제한
최대 2초. 자동 재시도 0회.
사용자가 대상을 수정하거나 승인한 뒤 새 요청으로 다시 검사한다.

## 예외 처리
소유권과 경로가 확인된 이번 실행의 임시 파일·빌드 결과 정리는 허용 목록으로 처리한다.
우회 승인은 대상·행위·기한을 제한하며 영구적인 전체 검사 해제로 저장하지 않는다.

## 출력 정책
훅 ID, 작업 종류, 마스킹된 대상 경로, 차단 이유, 다음 행동만 짧게 출력한다.
비밀 값, 전체 환경 변수, 자격 증명이 포함될 수 있는 명령 전체를 출력하지 않는다.

## 검사기 오류 처리
검사기 누락·오류·시간 초과를 허용으로 바꾸지 않는다. 위험 작업은 차단한다.
호스트가 차단을 지원하지 않으면 알림 전용으로 표시하고 사전 보호가 작동한다고 주장하지 않는다.

## 재검사 조건
명령, 실제 대상, 환경, 승인 범위가 바뀌면 새로 검사한다. 이전 허용 결과를 재사용하지 않는다.
