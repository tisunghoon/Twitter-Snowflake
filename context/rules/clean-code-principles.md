# 클린 코드 원칙

이 프로젝트에서 구현과 리뷰에 사용할 작성 기준이다.
알고리즘과 오류 정책의 확정 여부는 [결정 기록](../decisions.md)을 따른다.

## 이름으로 의미 드러내기

`lastTimestamp`, `workerId`, `sequence`처럼 값의 역할을 이름으로 표현한다.
시간은 절대 시각과 epoch 이후 경과 시간을 구분한다.
단위가 헷갈리는 값에는 `elapsedMillis`처럼 단위를 적는다.
`temp`, `data`, `value`만으로 여러 의미를 표현하지 않는다.

## 책임 나누기

단일 책임 원칙(SRP: 코드를 바꾸는 이유를 한 역할에 모으는 원칙)을 기준으로 나눈다.
생성기는 ID를 만들고, Decoder는 필드를 복원하고, Controller는 응답을 만든다.
짧은 함수를 만들기 위해 한 줄마다 메서드로 나누지는 않는다.
검사 순서와 상태 갱신을 함께 읽어야 하는 생성 과정은 흐름이 보이도록 유지한다.

## 상태 변경을 한곳에 모으기

현재 제안은 시간 읽기부터 상태 갱신까지 `nextId()` 전체를 같은 잠금으로 보호한다.
원자성(다른 호출이 작업 중간에 끼어들지 못하는 성질)을 깨는 함수 분리를 하지 않는다.
후보 순번은 지역 변수로 계산하고, 모든 검사에 성공한 뒤 상태를 저장한다.
예외가 발생하면 마지막 성공 시각과 순번을 보존한다.

## 규칙의 중복 줄이기

DRY(같은 지식을 여러 곳에서 따로 관리하지 않는 원칙)를 적용한다.
생성과 복원이 공유하는 비트 수, 마스크, epoch는 한곳에서 정의한다.
단, 테스트의 기대값을 구현 코드로 다시 계산하지 않는다.
예를 들어 알려진 입력의 기대 ID `4198400`을 직접 비교해 같은 계산 실수를 탐지한다.

## 오류와 경계 드러내기

유효하지 않은 워커 ID와 null Clock은 생성 시 거부한다.
시간 범위, 역행, 순번 소진은 설계에서 정한 순서대로 검사한다.
예외를 삼키거나 실패했는데 임의의 ID를 반환하지 않는다.
오류 메시지와 별개로 안정된 오류 코드를 제공한다.

## 필요한 만큼만 추상화하기

YAGNI(지금 필요하지 않은 기능은 미리 만들지 않는 원칙)를 적용한다.
현재 범위에 없는 DB, 분산 락, 자동 워커 할당, 재시도 프레임워크는 추가하지 않는다.
인터페이스는 교체할 구현이나 테스트 경계가 실제로 필요할 때 도입한다.

주석에는 잠금 범위, 비트 계산 이유, 재시작 보장의 한계처럼 코드만으로 알기 어려운 이유를 쓴다.
검증 가능한 작은 예시와 구체적인 조건으로 설명하고, “적절히 처리” 같은 표현을 피한다.
