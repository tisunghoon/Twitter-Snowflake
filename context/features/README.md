# 기능별 작업 안내

한 작업은 사용자 행동 하나를 끝까지 처리한다. 메인 에이전트가 필요한 계층을 연결한다.
새 컨텍스트 리뷰어만 별도로 두고 구현 담당을 계층별로 나누지 않는다.

## 상태
계획 중 → 승인 대기 → 구현 중 → 자체 검증 중 → 독립 리뷰 중 → 수정·재검증 → 커밋 완료.
검증 보류는 필수 검사나 독립 리뷰를 수행하지 못한 상태다.
차단은 미확정 설계나 선행 기능 때문에 시작할 수 없는 상태다.
문서 작성 완료와 기능 구현 완료를 구분한다.

## 파일
[템플릿](template.md)을 이용해 기능 폴더에 plan.md를 만든다.
verification.md에는 실제 실행 증거를, review.md에는 독립 리뷰와 수정 확인을 적는다.
[F-01](f-01-issue-id/plan.md), [F-02](f-02-error-recovery/plan.md),
[F-03](f-03-concurrent-issuance/plan.md), [F-04](f-04-multi-worker/plan.md) 계획이 있습니다.
Codex가 F-01 계획 재작성 후 F-01~04를 순차 완료했습니다. 현재 상태는 [기능 목록](../tasks.md), 실행·리뷰 근거는 각 기능의 verification.md와 review.md를 확인합니다.

## 완료 조건
승인된 성공·실패 경로 구현, 필수 검사 통과, 독립 리뷰 통과, 차단 결함 해소가 필요하다.
검토·검증한 소스와 커밋한 소스가 같아야 한다.
테스트 미실행이나 리뷰어 부재를 통과로 처리하지 않는다.
기반 작업은 기능에 필요한 최소 범위로 잡으며 사용자 기능 완료로 세지 않는다.

## 이슈에서 시작하기
[이슈 템플릿](../templates/issue.md)으로 요청을 작성하고 [실행 규칙](../rules/issue-execution.md)을 따른다.
plan.md는 이슈 URL·확인 날짜와 승인 계획을 연결한다. 이슈가 없으면 원문 요청 위치를 남긴다.
review.md는 [리뷰 템플릿](../templates/review.md), 사용자 보고는 [완료 보고](../templates/completion-report.md)를 사용한다.
