# F-01: ID 발급 결과 확인

## 상태와 승인
- 상태: 승인 대기. D-02~07 미확정으로 구현 차단.
- 담당: 구현 시작 시 메인 에이전트 하나를 지정.
- 선행 기능: 없음. 최소 빌드·검증 기반을 함께 준비.
- 기준 커밋 / 기존 변경: 구현 계획 확정 시 기록.
- 사용자 승인: 기능별 운영 방식만 승인. 이 기능의 구현 계획은 미승인.

## 사용자 행동과 범위
사용자가 ID 발급을 요청하면 ID와 복원된 시각·워커·순번을 받는다.
[설계](../../design.md)의 core·config·api를 끝까지 연결한다.
DB·UI·스테이징은 포함하지 않는다.

## 계약과 변경 예상
D-02~07과 버전 호환성을 확인해 확정한 뒤 구현한다.
예정 파일: 빌드·Wrapper, core 생성기·Decoder·오류, config 설정·Clock,
api 컨트롤러·DTO·예외 처리기, 관련 테스트와 검증 스크립트.
API 제안은 POST /api/ids, 성공 200, id 문자열과 복원 필드다.
필수 워커 설정을 검사한다. DB 변경은 없다.

## 완료 조건
알려진 입력 epoch+1ms / worker 1 / sequence 0의 ID는 제안 기준 4198400이다.
반환 필드는 실제 ID에서 복원하며 시계를 다시 읽지 않는다.
잘못된 워커와 null Clock은 거부한다.
역행·범위·소진·동시성 보호 등 최소 정확성 조건은 처음부터 구현·검사한다.
F-02·03은 이 보호를 미루는 작업이 아니라 외부 실패·동시 요청 시나리오를 확장하는 작업이다.

## 검증과 커밋 계획
[검증 안내](../../verification/README.md)의 환경 → 테스트·타입·빌드 → HTTP 확인을 수행한다.
현재 명령은 미구축이다. UI가 없으므로 브라우저 검사는 적용하지 않는다.
예정 단위는 최소 검증 기반과 ID 발급 기능이며 구체적인 분할은 승인 때 정한다.
실행 증거와 독립 리뷰를 확보한 뒤 해당 변경만 커밋한다.
