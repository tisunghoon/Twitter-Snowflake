# 기능 단위 검증

## 식별과 상태
- 훅 ID: H-03
- 정책 버전: 0.1
- 상태: 명세 작성 / 스크립트 미구축 / 호스트 미연결
- 아래 시간·명령은 구축 기준이며 실제 작동을 검증한 값이 아니다.

## 실행 시점
여러 수정을 마친 작업 단위 종료 시, 독립 리뷰 요청 전에 실행한다.
기능 경계를 알 수 없는 호스트에서는 명시적 명령으로 호출하며 매 파일 수정마다 실행하지 않는다.

## 적용 범위
해당 기능의 코드·테스트·API·설정과 빌드 입력을 대상으로 한다.
초기 작은 Java 프로젝트에서는 필수 Gradle 검사·빌드를 사용한다.
문서만 변경하면 문서 검사를 선택하고, API 구현 이후 실제 HTTP 검사를 연결한다.

## 입력과 증거
기능 ID, 승인된 AC·검증 계획, 기준 버전, 새 파일 포함 변경 목록을 받는다.
실행기가 검사 ID·명령·환경·종료 코드·테스트 건수·대상 내용 해시·보고서 위치를 기록한다.
직접 작성한 통과 문장이나 이전 실행 보고서로 이번 결과를 대신하지 않는다.

## 검사 명령
예정: `./scripts/verify.sh`.
내부 실행 단계는 [명령 안내](../verification/commands.md)를 따른다.
아직 Wrapper·스크립트가 없으므로 현재는 실행할 수 없다.

## 판정 기준
필수 검사 실패·미실행·시간 초과, 필수 테스트 0건, 태스크 미연결은 실패 또는 검증 보류다.
문서 전용 검사에는 코드 테스트 0건 규칙을 적용하지 않는다.
영향 범위가 불명확하거나 공통 설정이 바뀌면 검사 범위를 넓힌다.

## 실패 동작
독립 리뷰 준비 완료로 넘기지 않고 원인을 수정한 뒤 관련 검증을 다시 실행한다.
코드 오류와 환경 장애를 구분한다. 테스트 삭제·검사 완화로 실패를 숨기지 않는다.

## 시간 제한
초기 총 한도 5분, 자동 재시도 0회. 실제 측정 후 계획에 한도를 조정한다.
시간 초과 시 자신이 시작한 자식 프로세스와 서버를 정리하고 로그를 보존한다.

## 예외 처리
변경에 없는 UI·DB 검사는 적용하지 않음으로 기록한다.
필수 검증을 실행할 수 없으면 사유와 영향을 적어 검증 보류로 보고한다. 통과 우회는 없다.

## 출력 정책
검사 ID·실행 ID·실패 위치·짧은 원인·다음 행동·마스킹된 원본 로그 위치를 출력한다.
원본 로그를 포함해 비밀 값을 마스킹한다. 출력 축약 과정에서 원래 종료 코드를 잃지 않는다.

## 검사기 오류 처리
명령 누락·분석 실패·보고서 생성 실패는 검증 보류다.
그 결과를 완료 게이트가 통과로 읽지 못하도록 명시적인 상태를 남긴다.

## 재검사 조건
최종 검증 이후 관련 소스·테스트·빌드 설정·정책·의존성이 바뀌면 재검증한다.
검증 중 입력이 바뀌어도 결과를 무효화한다. 보고서만 추가된 경우 전체 검사를 반복하지 않는다.
