# 협업 규칙

역할과 권한의 기준은 [agent.md](../agent.md)다.
이 문서는 기존 약속을 구현·리뷰 중 확인하기 쉽게 정리한다.

## 담당과 책임

| 담당 | 책임 |
|---|---|
| 사용자 | 학습 목표와 프로젝트 방향 결정, 주요 설계 승인 |
| Codex | 개념 설명, 설계 제안, 작업 분해, 최종 코드 리뷰와 직접 검증 |
| 구현 Agy | 확정 설계에 따른 기능 구현, 테스트 작성·실행, 검토 자료 인계 |
| 질문 Agy | 개념·코드·오류 설명, 설계 변경 제안과 발견한 결함 전달 |

Codex의 구현 코드 작성은 별도 요청을 따른다.
질문 Agy는 별도 지시 없이 설계를 확정하거나 최종 검증 완료를 선언하지 않는다.
문서 작성과 다른 에이전트에게 실제 메시지를 보내는 행위는 구분한다.
전송 요청이 있을 때만 수신 대상을 확인하고 보낸다.

## 결정과 작업 범위

원문 사실, 추가 자료의 사실, 설계 제안, 사용자 확정을 구분한다.
문서를 읽었다는 말이나 답변이 없다는 사실을 설계 승인으로 취급하지 않는다.
사용자가 위임한 결정은 이유를 적고, 위임하지 않은 주요 결정은 확인한다.
확정 상태는 [decisions.md](../decisions.md)에, 작업 의존성과 차단 사유는 [tasks.md](../tasks.md)에 기록한다.

기존 답과 저장소를 먼저 확인한다. 이미 답한 질문과 승인한 작은 작업을 반복해서 묻지 않는다.
현재 요청을 DB·UI·운영 배포 같은 별도 프로젝트로 확대하지 않는다.
미확정 계약에 의존하는 구현은 실행 가능으로 표시하지 않는다.

## 변경 보존과 순차 작업

작업 시작 전에 변경 상태를 확인한다. 사용자와 다른 에이전트의 변경을 되돌리지 않는다.
담당 파일과 목적을 명시하고, 동시에 같은 파일을 수정해야 하면 먼저 조율한다.
이번 규칙 문서는 하나를 작성하고 확인한 뒤 다음 파일로 진행한다.
작업별 추가 지시 없이 병렬 에이전트를 실행하지 않는다.

## 설명과 인계

설명은 쉬운 예시와 실제 용어를 연결한다. 비유의 한계도 밝힌다.
인계에는 변경 파일, 커밋 또는 diff, 실행 환경, 실행 명령, 결과, 남은 제한을 담는다.
다른 담당자의 통과 보고와 직접 실행한 결과를 구분한다.
발견한 문제는 심각도·파일 위치·재현 근거·기대 동작으로 기록한다.

최종 판정은 통과 / 수정 필요 / 검증 보류 중 하나로 남긴다.
필수 검증을 실행하지 못했거나 결함이 남아 있으면 전체 완료로 표시하지 않는다.
