# 자동 테스트

## 현재 상태
준비 예정. 제품 코드와 테스트, 테스트 실행 태스크는 없다.
아래 기대값은 [설계 초안](../design.md)의 정책이 채택될 경우의 기준이다.

## 목적과 사전 조건
정상 동작뿐 아니라 경계값, 실패 후 상태, 동시 호출의 결과를 검사한다.
[테스트 데이터](test-data.md)의 독립된 생성기와 제어 가능한 Clock을 사용한다.
core 테스트는 Spring 서버 없이 실행한다. API와 설정 테스트는 필요한 Spring 기능을 사용한다.

## 실행 방법
구축 후 `./gradlew test`로 실행한다. 채택한 별도 테스트 태스크가 있으면 전체 검사에 연결한다.

| 사례 | 기대 결과 |
|---|---|
| epoch, worker 0, 첫 발급 | ID 0, sequence 0 |
| epoch+1ms, worker 1, 첫 발급 | ID 4198400, 복원 필드 일치 |
| 같은 ms에 4096회 후 추가 발급 | 0~4095 발급, 추가 호출은 소진 오류 |
| 소진 후 다음 ms | sequence 0으로 회복 |
| 시간 10→9→10→11ms | seq0 → 역행 오류 → seq1 → seq0 |
| epoch 이전, 마지막 유효 ms, 그 다음 | 범위 오류 → 성공 → 범위 오류 |
| worker -1·1024, null Clock | 생성 거부 |
| 워커 설정 누락·범위 초과 | 서버 시작 실패 |
| 고정 ms, 8스레드 × 256회 | 성공 2048건, 고유 ID 2048개 |
| 같은 ms, worker 1·2 각각 2048회 | 합계 4096개 고유 |
| HTTP 성공·도메인 오류 | id 문자열, 복원 필드, 약속한 503 code |
| 음수 ID 복원 | 입력 거부 |

## 성공 기준
모든 Future를 회수하고 스레드 내부 예외도 실패로 드러낸다.
실패 호출 뒤 상태 보존과 정상 시간 복귀를 확인한다.
단일 생성기의 순차 성공 ID는 증가해야 한다. 동시 응답 도착 순서는 검사 기준이 아니다.
테스트 결과와 건수를 기록하고 필수 사례가 누락되면 전체 완료로 표시하지 않는다.

## 실패 시 확인과 정리
입력 시각·워커·호출 수·실제 결과를 비교한다. sleep을 늘려 실패를 숨기지 않는다.
동시성 테스트에 종료 제한을 두고 executor를 항상 종료한다.
실패한 테스트의 보고서와 재현 조건은 유지한다.
